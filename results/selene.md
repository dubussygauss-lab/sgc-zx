# Selene (local emulator) runs of the compiled circuits

Generated by `selene/make_summary.py` from `results/selene_noiseless.csv` and `results/selene_depolarizing.csv` (produced by `selene/run_selene.py`; tests in `selene/test_selene.py`; error-model probe in `selene/calibrate_error_model.py`). Nothing was submitted to Nexus or any cloud service; every run is `selene-sim` 0.3.4 on the local 2-core container.

Tags: [F] verifiable from the CSVs or by rerunning the scripts; [O] judgement or assumption.

## 1. Route that works

[F] `results/compiled/<pipeline>/<file>.qasm` (hqslib1 header; gates `rz`, `U1q`, `RZZ`, `measure q[j] -> c[i]`) -> `pytket.qasm.circuit_from_qasm` (OpTypes Rz, PhasedX, ZZPhase, Measure) -> `guppylang.guppy.load_pytket(name, circ)` (signature `array[qubit, n] -> array[bool, n]`) -> a guppy `main` that allocates `n` qubits, calls the loaded function, `discard_array`s the qubits and emits `result("c", bits)` -> `selene_sim.build(main.compile())` -> `runner.run_shots(Quest(random_seed=s), n_qubits=n, n_shots=2000, error_model=..., random_seed=s)`.
[F] `load_pytket` accepted PhasedX, Rz, ZZPhase and Measure directly on every one of the 468 compiled circuits; no rebase, no HUGR export and no gate substitution was needed. The ZZPhase/U1q rejection anticipated in the brief did not occur.
[F] Bit order: the `result("c", ...)` array is in classical-bit order c[0..n-1]; the bitstring `"".join(c)` therefore has c[0] as its most significant bit, the convention of `bench/family_A/*.npy` and `compile.probs_from_measured_qasm`. `selene/test_selene.py::test_measure_map_permutation` checks this with X on q[0] (and on q[2]) and the map q[0]->c[2], q[1]->c[0], q[2]->c[1] (expected strings 001 and 010; both the Selene sample and `probs_from_measured_qasm` put all mass there).
[F] Operational gotchas: (i) every proxy variable (`HTTPS_PROXY`, `https_proxy`, `HTTP_PROXY`, `http_proxy`, `NO_PROXY`, `no_proxy`) must be unset or Selene's local TCP result stream hangs (the script pops them itself); (ii) `guppy.load_pytket` needs a unique function name per circuit in a process; (iii) the first `build` in a process costs about 5-10 s (toolchain warm-up), later builds 0.2-0.6 s; (iv) `run_shots` has its own `n_processes` argument, but circuits were parallelised instead with a 2-process `multiprocessing` spawn pool (one `run_shots` call per circuit, `n_processes=1`), which Selene allowed without conflicts.
[F] Seeding: `random_seed = sha256(pipeline/file/tag)[:4]`, stored in the CSV column `seed`; `test_seed_reproducible` checks that the same seed reproduces the counts exactly and a different seed does not.

## 3. Depolarising runs versus the density-matrix proxy

[F] `selene_sim.DepolarizingErrorModel(random_seed=None, p_1q=0.0, p_2q=0.0, p_meas=0.0, p_init=0.0)` (signature read with `inspect.signature`). The user guide gives no convention, so `selene/calibrate_error_model.py` measured it (20000 shots per probe, p = 0.3):

```
shots per probe: 20000
Rz x20, p_1q=0.3: P(1)                     0.0000 +/- 0.0000   predictions: 0 if Rz noiseless; (1-(1-2f)^20)/2 = 0.5000 (f=2p/3) / 0.4996 (f=p/2) if noisy
PhasedX(0,0) x20, p_1q=0.3: P(1)           0.5006 +/- 0.0035   predictions: 0 if zero-angle gates are free; (1-(1-2f)^20)/2 = 0.5000 (f=2p/3) / 0.4996 (f=p/2) if noisy
X, p_1q=0.3: P(flip)                       0.2051 +/- 0.0029   predictions: 2p/3=0.200 (non-identity Pauli) / p/2=0.150 (any Pauli)
ZZPhase, p_2q=0.3: P(not 00)               0.2442 +/- 0.0030   predictions: 12p/15=0.240 (non-identity Pauli) / 12p/16=0.225 (any Pauli)
measure |0>, p_meas=0.3: P(1)              0.3061 +/- 0.0033   predictions: p=0.300 if symmetric flip
measure |1>, p_meas=0.3: P(0)              0.3038 +/- 0.0033   predictions: p=0.300 if symmetric flip
init, p_init=0.3: P(1)                     0.2979 +/- 0.0032   predictions: p=0.300 if init flip; 2p/3=0.200 if depolarising
```
[F] Reading of the probe: Rz is noiseless (0 flips in 20000 shots after 20 Rz gates at p_1q = 0.3); a zero-angle PhasedX still receives noise; after one X gate the flip rate is 0.2051 +/- 0.0029 against 2p/3 = 0.200 for 'uniformly random non-identity Pauli with probability p' and p/2 = 0.150 for 'uniformly random Pauli including identity'; after one ZZPhase the rate of leaving 00 is 0.2442 +/- 0.0030 against 12p/15 = 0.240 (non-identity) and 12p/16 = 0.225 (any Pauli); p_meas is a symmetric readout flip (0.3061 and 0.3038 on |0> and |1>); p_init flips the prepared state with probability p (0.2979). [O] These are the conventions of `noise/dm_sim.py` (p1: (1-p) rho + p/3 sum P rho P; p2: (1-p) rho + p/15 sum P rho P; Rz virtual), so the two models agree gate by gate except that the proxy's readout flip is asymmetric (9e-4 / 1.8e-3) while Selene's is one number.
[F] Parameters: p_1q = 7.3e-5, p_2q = 1.29e-3 (H2-2E defaults, `docs/platform_notes.md` 3.3). Two variants: `gates_only` (p_meas = p_init = 0) and `gates_meas_init` (p_meas = 1.35e-3 = mean of the H2-2E 0-outcome and 1-outcome flip rates [O: assumption, Selene has one symmetric rate], p_init = 4e-5). The proxy column is `results/family_A_proxy_h22e.csv` / `results/family_B1_proxy_h22e.csv` (noise set `NOISE_H22E`: p1, p2, p_meas_0, p_meas_1, p_init), so `gates_meas_init` is the like-for-like comparison and `gates_only` is expected to sit above the proxy.
[F] Comparison statistic: the proxy's F_H is exact (density matrix) while Selene's is from 2000 shots, and a finite sample biases F_H downward. So for each run the proxy's noisy distribution was regenerated with `noise/dm_sim.py` (the same code that produced the proxy CSV; its exact F_H is reproduced in `F_H_proxy_exact`), 400 multinomial samples of 2000 shots were drawn from it, and their F_H mean and sd (`F_H_proxy_sampled_mean`, `F_H_proxy_sampled_sd`) are the prediction and the sampling error for Selene's `F_H_selene_depol`. `z = (F_H_selene_depol - F_H_proxy_sampled_mean) / F_H_proxy_sampled_sd`; `agree_2sd` = |z| <= 2. `F_H_selene_noiseless_sameseed` is the noiseless sample with the same seed (shows the pure sampling bias). `TVD_selene_vs_proxy` and `TVD_expected_sampling` compare the two distributions directly.
